## 一、一句话结论

> **Cloudflare 免费版对国内用户是「可达但不快」。**
> 它不是「更好的服务器」，而是**换了一种代价结构** —— 把运维复杂度换成了运行时约束和供应商绑定。

实测数据（手机 4G，无任何代理）：

| 地址 | 链路 | 结果 |
| --- | --- | --- |
| `cf-lab.your-account.workers.dev` | CF workers.dev | ❌ **打不开** |
| `lab.example.com` | 自定义域名 → CF 边缘 | ✅ 能开，**明显偏慢** |
| `example.com` | 灰云直连腾讯云广州 | ✅ **秒开** |

这三行决定了 CF 在国内技术栈里的位置，后面所有判断都由它推导。

## 二、认知框架

### 2.1 Cloudflare 是三样东西，不是一样

```
                  ┌─────────────────────────────┐
   传统认知  ───→ │  CDN + DNS                  │  ← 大多数人以为只有这个
                  ├─────────────────────────────┤
   实际重心  ───→ │  开发者云（Workers 生态）    │  ← 战略核心，新产品都长在这
                  ├─────────────────────────────┤
                  │  企业安全（WAF/Zero Trust）  │
                  └─────────────────────────────┘
```

后台侧栏的分组就是这三块：

| 侧栏分组 | 内容 | 通俗理解 |
| --- | --- | --- |
| **域名** | DNS 解析、域名注册、Zone 管理 | 所有 Zone 级功能的入口 |
| **Observe** | Investigate（日志排查）、数据分析 | 出问题来这看 |
| **构建 · 计算** | Workers、Containers | **CF 自己的云平台** |
| **构建 · AI** | Workers AI、AI Gateway、Vectorize、AutoRAG | 边缘 AI |
| **构建 · 存储和数据库** | R2、D1、KV、Durable Objects、Queues | Workers 的数据层 |
| **构建 · Images & Stream** | 图片处理托管、视频转码点播 | 图床 + 视频云 |
| **构建 · Realtime** | WebRTC / 实时音视频 | 直播、会议 |
| **保护 · 应用程序安全** | WAF、DDoS、Bot 管理、速率限制 | 网站防护，**要橙云才生效** |
| **保护 · Zero Trust** | Access、Gateway、Tunnel、WARP | 保护**内网系统和员工设备**，替代 VPN |
| **保护 · 联网** | Magic Transit / Magic WAN | 企业整网接入 |
| **交付和性能** | CDN 缓存、Argo、负载均衡、Waiting Room | 传统意义的 CDN |

> 首页三张卡片的准确含义（容易误解）：
> - **Ship something new** = 把应用部署到 **CF 自己的服务器**（Workers），不是发布你已有的站
> - **Add a domain** = 把域名接入 CF（或在 CF 注册新域名）
> - **Protect apps and users** = **Zero Trust**，管「谁能访问你的内部系统」，不是给公网站加 WAF

### 2.2 Workers 是什么

名字来自浏览器的 **Service Worker** —— 一段拦截并处理 HTTP 请求的脚本。CF 把这个模型搬到了全球边缘节点。

```
传统服务器                        Cloudflare Workers
┌────────────────────┐            ┌────────────────────┐
│  完整 Linux 系统    │            │  V8 isolate 沙箱   │  ← Chrome 的 JS 引擎
│  ├ 进程常驻         │            │  ├ 请求来才活      │
│  ├ 监听 :8000       │            │  ├ 无端口概念      │
│  ├ 有文件系统       │            │  ├ 无文件系统      │
│  └ 想装啥装啥       │            │  └ 只有 JS/WASM    │
└────────────────────┘            └────────────────────┘
     启动 秒级                          启动 <5ms
```

**不是虚拟机也不是容器**，是在一台物理机上塞几千个 V8 沙箱。这样才能做到全球 300 个节点各自部署你的代码、冷启动 5 毫秒。代价是没有完整操作系统。

#### Workers 的三个用法层次

| 层次 | 用法 | 生产环境占比 |
| --- | --- | --- |
| **1. 边缘胶水层** | 不替代后端，只在流量路过时加工：A/B 测试、灰度、鉴权前置、请求改写、地理路由、给老系统贴补丁 | **最主流** |
| **2. BFF / API 网关** | 聚合多个后端服务，给前端一个接口 | 常见 |
| **3. 完整应用后端** | 前端 + API + 数据库全在上面 | 中小项目 / 新项目 |

最好的类比：**Workers ≈ 托管版、全球版的 OpenResty（nginx + Lua）**。

```
OpenResty                        Cloudflare Workers
在自己机器上做请求加工      →     在全球 300 个边缘节点做
用 Lua 写                         用 JS/TS 写
自己运维                          平台托管
一台机器                          天然全球分布
```

### 2.3 绑定（Bindings）—— Workers 最核心的设计

资源不通过连接字符串获取，而是在配置里声明，运行时由平台注入。

```
传统方式                          Workers 绑定
────────────────                 ────────────────
连接字符串写在 appsettings        wrangler.jsonc 声明 binding
new SqlConnection(connStr)        直接用 env.DB
走网络 TCP 连数据库                运行时注入，无连接字符串、无密码
密码可能泄露到 git                 凭据根本不存在于代码里
```

配置改了要跑 `npx wrangler types` 重新生成 `Env` 类型，否则 TS 里没提示。**配置驱动类型**。

### 2.4 Zone 级 vs Worker 级 ⭐ 理解 CF 的第一把钥匙

| 类别 | 功能 | 需要域名接入 CF？ |
| --- | --- | --- |
| **Worker 级** | Workers、D1、KV、R2、Cron、Secrets、Rate Limiting binding、Logs | ❌ 注册账号即可 |
| **Zone 级** | WAF、缓存规则、Bot 防护、页面规则、Analytics、自定义域名 | ✅ 必须先接入域名 |

**这个边界在 OAuth scope 层面就划死了**。`wrangler whoami` 会显示：

```
- workers (write)      ← 能建改删 Worker
- d1 (write)           ← 能建数据库
- zone (read)          ← 只读！
```

所以 **wrangler 管不了 DNS、WAF、缓存规则**，那些只能走后台、API、Terraform，或者 CF 官方 MCP。

### 2.5 橙云 vs 灰云 ⭐ 第二把钥匙

DNS 记录旁边那朵云决定流量走不走 CF：

```
🟠 橙云 (Proxied)   →  用户 → Cloudflare → 你的源站    （走代理）
⚪ 灰云 (DNS only)  →  用户 ─────────────→ 你的源站    （只做解析）
```

| 功能 | 要橙云吗 |
| --- | --- |
| CDN 缓存、WAF、Bot、速率限制、L7 DDoS、SSL 卸载、Argo、负载均衡、流量分析 | ✅ **必须**，灰云下全部失效 |
| DNS 解析托管、域名注册、DNSSEC | ❌ 灰云即可 |
| Workers、Pages、R2、D1、Workers AI、Zero Trust/Tunnel | ❌ 独立产品，域名都不用接 |

**实践意义**：可以「只用 CF 的一部分」。把域名接进来但全挂灰云 —— 只享受它的高速 DNS，流量还是直连原服务器，国内速度一点不受影响。想试缓存时把某条记录点成橙云，不行再点回来，30 秒的事。

### 2.6 Static Assets 的路由规则（实测确认）

```
请求进来
  ├─ 匹配到静态文件？ → 返回文件           （/、/assets/*.js）
  └─ 没匹配到        → 交给 Worker        （/api/、/about）
                        Worker 返回啥就是啥
```

两个反直觉的点：

- `not_found_handling: "single-page-application"` **在配了 Worker 时不会自动兜底**，Worker 必须自己调 `env.ASSETS.fetch(request)`
- `/api/*` **不需要** `run_worker_first` 就能正确进 Worker

### 2.7 免费提供的域名

`*.workers.dev` 就是 CF 的免费域名。地址结构：

```
https://cf-hello.your-account.workers.dev
        └───┬──┘ └────┬───┘ └────┬────┘
      Worker 名字  账号子域    固定后缀
```

| 段 | 能改吗 |
| --- | --- |
| Worker 名字 | ✅ 改 `wrangler.jsonc` 的 `name` 再 deploy（会新建 Worker，旧的要手动删） |
| 账号子域 | ⚠️ 后台可改，但旧 URL 全失效，有次数限制 |
| `workers.dev` | ❌ 固定 |

**CF 不送可注册的域名**，但 **Cloudflare Registrar 按批发成本价卖**，不加价、不玩「首年 1 美元续费 200」那套。.com 约 $10/年。

## 三、中国大陆访问的真相（实测）

**这一节是本文最有价值的部分。**

### 3.1 两个独立的问题，别混为一谈

| 问题 | 成因 | 换自定义域名能解决吗 |
| --- | --- | --- |
| **访问不了** | `workers.dev` 这个域名在大陆不通 | ✅ **能解决** |
| **慢**（几百 ms） | CF 免费版大陆无节点，流量出境 | ❌ **解决不了** |

所以绑自己的域名不只是「好看」，**是让国内能打开的前提**。

### 3.2 实测数据

**手机 4G，关闭全部代理：**

```
cf-lab.your-account.workers.dev   ❌ 打不开
lab.example.com             ✅ 能开，明显偏慢
example.com                 ✅ 秒开（灰云直连腾讯云广州）
```

**边缘机房调度**（看响应头 `cf-ray` 后缀）：

```
cf-ray: a34e634fc9d0a11a-PDX
        └────────┬───────┘ └┬┘
           请求唯一 ID      机房代码
```

实测被调度到 **PDX（波特兰）/ SJC（圣何塞）**，不是香港、不是东京 —— 太平洋对岸。

> `cf-ray` 是排查 CF 问题最常用的响应头。报错时把它给 CF 支持，能精确定位到那一次请求。

### 3.3 慢在哪：不是计算，是网络

| 环节 | 耗时 |
| --- | --- |
| Worker 冷启动 | **5 ms** |
| Worker 执行 | < 1 ms |
| 网络往返（国内 ↔ 美西） | **600 ms+** |

**99% 的延迟是网络往返，和 Cloudflare 的计算性能一点关系没有。**

### 3.4 D1 的额外惩罚

D1 是**单主库架构，所有写入必须回到主库**。如果主库区域选错：

| 主库区域 | 从广东写一条数据 |
| --- | --- |
| WNAM（美西） | 约 600 ms+ |
| APAC（亚太） | 约 60~120 ms |

建库时**必须显式 `--location=apac`**。不加的话 CF 按创建请求的来源 IP 判断 —— **开着代理就会被放到代理出口所在的区域**。

D1 支持**全球只读副本**（`read_replication`），开启后读请求就近走副本，写仍回主库。免费版可用，默认 `disabled`。

### 3.5 备案问题

| 做法 | 风险评估 |
| --- | --- |
| NS 切到 CF，`@` / `www` **挂灰云**指向原备案 IP | 较低 —— 主域仍解析到备案 IP，只是换了 DNS 服务商 |
| 只拿子域挂橙云 | 较低 —— 备案核查主要看主域 |
| `@` / `www` 也挂橙云（源站 IP 被隐藏） | **较高** —— 容易触发核查 |

**没有担保，这是自己的域名自己判断。** 但可回滚：NS 改回原服务商即可。

## 四、免费额度与成本安全

### 4.1 额度

| 资源 | 免费额度 |
| --- | --- |
| Workers 请求 | 10 万 / 天 |
| Workers CPU | 10 ms / 请求 |
| Pages 流量 | 无限 |
| D1 存储 | 5 GB |
| D1 读 / 写 | 500 万行 / 10 万行 每天 |
| KV 读 | 10 万 / 天 |
| R2 存储 | 10 GB，**出站流量免费** |
| DDoS 防护 | 无限量 |

### 4.2 ⭐ 不绑卡 = 账单上限为 0

**这条被严重低估。**

个人项目最怕的翻车方式：写了个 bug 死循环调用，或被人刷接口，第二天收到天价账单 —— AWS/GCP 上这种故事一堆。

**Workers Free 计划没有绑卡就没有计费通道**，超了额度直接返回 429 停服，**账单上限是 0**。对个人项目是巨大的安全垫。

⚠️ 反过来：一旦升级 Workers Paid（$5/月），就变成按量计费，那时记得设 budget 告警。

⚠️ **R2 需要绑卡才能开通**，即使在免费额度内。

### 4.3 R2 的「出站流量免费」值得单独说

S3 和腾讯云 COS 的**流量费才是大头**，存储反而便宜。R2 出站免费这一条，做图床/CDN 源站时是真省钱。

## 五、域名接入 Cloudflare 完整记录

### 5.1 前提认知：免费版不能只接一个子域

Cloudflare 的「子域委派」（把 `lab.example.com` 单独作为一个 zone）是**付费套餐功能**。免费版只能整域接管 —— 整个域名的 NS 必须指向 Cloudflare。

**但这不等于主站解析会变：**

```
接入前：
  腾讯云 DNSPod（NS）
    ├── @    A → 203.0.113.10
    ├── www  A → 203.0.113.10
    └── zp   A → 203.0.113.20

接入后：
  Cloudflare（NS）
    ├── @    A → 203.0.113.10   ⚪ 灰云 → 用户直连，和之前一模一样
    ├── www  A → 203.0.113.10   ⚪ 灰云
    ├── zp   A → 203.0.113.20  ⚪ 灰云
    └── lab  → Worker             🟠 橙云 → 只有这个走 CF
```

**灰云记录的解析结果完全相同，用户流量不经过 CF 一个字节。** 变的只是「谁来回答 DNS 查询」。

| 你的诉求 | 能做到吗 |
| --- | --- |
| 主站解析结果不变 | ✅ |
| 主站流量不走 CF | ✅ 灰云 = 直连 |
| 只有子域走 CF | ✅ |
| 备案 IP 保持不变 | ✅ |
| **NS 服务商不变** | ❌ **做不到** |

### 5.2 换 NS 的实际影响

| 影响 | 评估 |
| --- | --- |
| 解析速度 | CF 的 DNS 是全球最快之一，大概率比 DNSPod 免费版还快 |
| 单点依赖 | CF 挂了整个域名受影响（概率极低但存在） |
| 原 DNS 控制台 | 不再生效，改记录去 CF |
| **可回滚性** | ✅ NS 改回原服务商即可 |

### 5.3 操作步骤

| 步 | 做什么 | 风险 |
| --- | --- | --- |
| 1 | **备份现有全部 DNS 记录**（截图 + 文本） | — |
| 2 | CF 后台 Add a domain，选 **Free** 套餐 | 无 |
| 3 | 核对自动扫描结果，**补全缺的、云朵全点灰** | 无 |
| 4 | 拿到 CF 给的两个 NS 地址 | 无 |
| 5 | **注册商处**改 DNS 服务器 | **唯一有风险的一步** |
| 6 | 等传播 + 验证解析结果没变 | — |
| 7 | 绑定 Worker 到子域 | 无 |

#### ⚠️ 第 5 步改的是「注册商的 DNS 服务器」，不是解析记录

```
腾讯云控制台
  └── 域名注册 → 我的域名 → xxx.com
        └── 管理 → DNS 服务器 → 【修改】     ← 改这里
  ✗ 不是 DNSPod → 解析记录
```

会提示「该域名正在使用 DNSPod 解析，修改后解析将失效」—— 正常，确认即可。

**原 DNS 服务商的解析记录先别删**，留着当备份，跑稳几天再清理。

### 5.4 验证方法（重要）

#### 判断注册局收没收到 —— 比查解析器可靠

递归解析器有缓存，**看它还是旧 NS 不代表变更失败**。要查注册局的权威数据：

```bash
curl -s https://rdap.org/domain/example.com | python3 -m json.tool
```

看 `nameservers` 和 `last changed`。注册局显示已改，剩下的就是等缓存过期。

#### 多视角看传播进度

```bash
# 阿里（国内视角）
curl -s -H "accept: application/dns-json" \
  "https://dns.alidns.com/resolve?name=example.com&type=NS"
# Cloudflare 视角
curl -s -H "accept: application/dns-json" \
  "https://cloudflare-dns.com/dns-query?name=example.com&type=NS"
# Google 视角
curl -s "https://dns.google/resolve?name=example.com&type=NS"
```

本次实测传播过程：注册局 19:10 接受 → 十几分钟后 CF/Google 已切换、阿里仍缓存 → CF 后台随后转 Active 并发邮件。

#### 最关键的验证：确认解析结果没变

```bash
# 经 CF 的 NS 查，结果应与迁移前逐字节一致
for h in example.com www.example.com; do
  curl -s -H "accept: application/dns-json" \
    "https://cloudflare-dns.com/dns-query?name=$h&type=A"
done
```

### 5.5 绑定 Worker 到自定义域名

```jsonc
"routes": [
	{ "pattern": "lab.example.com", "custom_domain": true }
]
```

`npm run deploy` 后 CF 自动：**建 DNS 记录 → 签发证书 → 绑路由**。

白捡三样东西：

| | 说明 |
| --- | --- |
| **IPv6** | 自动给 AAAA，源站没 IPv6 也能被 IPv6-only 用户访问 |
| **证书全托管** | Google Trust Services 签，90 天自动续，不需要 certbot / 续期 timer / 证书路径 |
| **源站 IP 隐藏** | 解析到 CF Anycast IP，扫描器看不到真实服务器 |

⚠️ **副作用**：加了 `routes` 后 `workers.dev` 会被自动禁用（404 / error 1042）。**这是好的默认值** —— 生产环境本来就该关掉它，否则别人绕过你的域名直接访问，能躲掉 zone 上的 WAF 和缓存规则。

## 六、决策框架：什么该放 CF

### 6.1 不是「大公司 vs 小项目」，而是「工作负载适不适合边缘」

常见误解是「只有个人小项目才用 Workers」。实际上 Shopify（Oxygen 店面托管）、Discord、DoorDash 都在用，而且有一个被严重低估的场景：

> **现代前端框架的 SSR 层。** Next.js / Nuxt / Remix / SvelteKit / Astro 全都支持部署到 Workers。Vercel 和 Netlify 的 Edge Functions 底层就是同类 V8 isolate 技术。大量商业网站的服务端渲染层已经跑在边缘运行时上，用户感知不到。

### 6.2 判断表

| ✅ 适合放 Workers | ❌ 不适合 |
| --- | --- |
| 静态站 + SSR | 复杂事务型业务系统 |
| API 网关 / BFF | 长任务、批处理、报表生成 |
| 鉴权、限流、WAF 前置 | 重 CPU（转码、大模型推理） |
| Webhook 接收器 | 大量存量 Java/.NET 代码 |
| 图片/视频处理管道 | 要连 SQL Server / Oracle |
| AI 推理网关 | **国内业务**（无大陆节点 + 备案） |
| 实时协作（DO + WebSocket） | 强合规、数据不出境 |
| 全球低延迟、读多写少 | 内网系统 |

### 6.3 真正的障碍不是「语言少」

| 障碍 | 说明 |
| --- | --- |
| **事务模型** | D1 是 SQLite，没有分布式事务，复杂业务多表一致性做不了 |
| **CPU 限制** | 10ms（免费）/ 30s（付费），报表、批处理不够 |
| **供应商锁定** | `env.DB`、`env.KV` 是 CF 专有 API，代码迁不走 —— **CTO 最怕的一条** |
| **生态断层** | 公司的 Java/.NET 中间件、内部 SDK、监控体系全废 |
| **合规与数据驻留** | 金融、医疗要求数据不出境；大陆无节点 |
| **人的问题** | 团队会 Spring/ASP.NET，不会边缘那套心智模型 |

> 语言这件事在变：Python 已有原生支持，Rust/Go/C++ 可编 WASM，**Containers**（2025 年推出）能跑 Docker 镜像。但 Containers 是付费产品，且定位是给 Workers 打辅助（按需拉起、跑完就停），**不是常驻服务器**。

### 6.4 「AI 生成的个人项目」特别适合 CF —— 但有三条冷水

**适合的理由：**

| | |
| --- | --- |
| 部署摩擦≈0 | 5 秒上全球，不碰服务器 |
| **JS/TS 恰好是 AI 写得最准的语言** | 语料最多；Workers API 面小（就 Web 标准那套），幻觉率低 |
| **不绑卡 = 硬性成本上限** | 见 4.2 |

**三条冷水：**

1. **「不改代码」≠「不用懂」** —— 你得能看懂 `Exceeded CPU limit`、D1 写入变慢、`--local`/`--remote` 混淆这类报错，AI 帮不了你
2. **锁定对「不改代码的人」伤害更大** —— 没打算维护这份代码，就等于把项目永久绑在 CF 上，没有 B 计划
3. **国内用户这条过不去** —— 和代码质量无关

### 6.5 现实的用法是混合

```
                    ┌─────────────────────────┐
   海外/静态流量  →  │  Cloudflare 边缘         │
                    │  · 前端静态资源          │
                    │  · 边缘鉴权 / 限流       │
                    │  · 图片托管 (R2)         │
                    └───────────┬─────────────┘
                                │ 回源
                    ┌───────────▼─────────────┐
   国内业务流量  →  │  腾讯云 / 阿里云          │
                    │  · 业务 API              │
                    │  · 数据库                │
                    └─────────────────────────┘
```

### 6.6 和自建部署的对比

| 环节 | 自建（nginx + Docker） | Workers |
| --- | --- | --- |
| 构建 | 本地 build → 传产物 | `npm run deploy` 一条命令 |
| 运行时 | docker compose up -d | 无 |
| 反代 | nginx 配置 + reload | 无 |
| HTTPS | certbot + 续期 timer | 自带 |
| 端口/安全组 | 手动开 | 无端口概念 |
| 负载均衡 | upstream + zone + 健康检查 | 天然全球分布 |
| 回滚 | 重新部署旧镜像 | 点一下版本 ID |
| 日志 | Serilog 写文件 | 平台内置 |
| 备份/fail2ban/监控 | 一堆活 | 大部分不需要 |
| **代价** | — | 运行时受限 + 供应商绑定 + 国内慢 |

## 七、测量方法学：别被自己的代理骗了

**这一节是本次实操中最容易被忽略、但最该记住的一条。**

### 7.1 清环境变量 ≠ 绕过代理

本次实测中一度得出「国内直连 CF 是 638ms」的结论，**这个结论不成立**。

原因：Clash 运行在 **TUN 模式**，在**网络层**接管流量。清掉 `HTTP_PROXY` / `HTTPS_PROXY` 环境变量，只是绕过了应用层的 HTTP 代理，**流量仍被 TUN 截走**。

```
清掉 HTTP_PROXY  →  只绕过了 HTTP 代理这一层
                 →  流量仍被 TUN 在网络层截走
```

两次测量的真实路径：

| 标注 | 实际 |
| --- | --- |
| 走代理 964ms | 应用 → HTTP 代理 → Clash → 境外（多一跳） |
| ~~国内直连~~ 638ms | 应用 → TUN → Clash → 境外 |

**两次都出境了，没有一次是真正的国内直连。**

### 7.2 怎么识别 TUN 在起作用

```bash
# 域名解析成 198.18.x.x = Clash TUN 的 fake-ip
getent hosts example.com

# 路由指向 tun 网卡
ip route get 198.18.0.131
#   → via 198.18.0.2 dev eth1 src 198.18.0.1

# 查真实公网出口（必须用国内服务，否则查到的是代理出口）
curl -s http://ip.3322.net
```

### 7.3 可信的测量方式

| 要测什么 | 怎么测 |
| --- | --- |
| 国内真实可达性与速度 | **手机流量，关闭全部代理** ← 最可信 |
| DNS 解析 | DoH 查询（绕开 fake-ip），多个解析器交叉验证 |
| NS 变更是否被接受 | RDAP 查注册局，不查递归解析器 |
| 边缘机房调度 | 响应头 `cf-ray` 后缀 |

### 7.4 教训

> **在有全局代理的机器上，任何「延迟/可达性」测量都要先确认链路，否则结论是错的。**
> 本次两个关键结论（能不能访问、快多少）最终都是靠**手机 4G 关代理**才拿到可信数据。

## 八、踩坑总表

### 8.1 Workers / 项目

| 坑 | 现象 | 解 |
| --- | --- | --- |
| 项目放 WSL 挂载盘 `/mnt/*` | `npm install` 慢 5~10 倍、热更新不触发 | 放 WSL 原生路径 `~/projects` |
| `compatibility_date` 填未来日期 | `Compatibility date "xxx" is in the future and unsupported` | 填 ≤ 本地 workerd 版本的日期；最省事让 C3 自动填 |
| C3 卡在 `AGENTS.md` 提问 | 命令中断，`wrangler.jsonc` 残留占位符 | 加 `--no-agents` |
| 官方 Vue 模板 `/about` 开箱 404 | `not_found_handling` 在有 Worker 时不兜底 | 加 `assets.binding: "ASSETS"`，Worker 兜底 `env.ASSETS.fetch(request)` |
| 改绑定没重新生成类型 | TS 里 `env.DB` 报未定义 | `npx wrangler types` |
| CPU 超 10ms | `Exceeded CPU limit` | 注意是 **CPU 时间**不是墙钟时间，等 I/O 不算 |
| 用 Node 专有 API 没开兼容 | 部署报找不到模块 | `compatibility_flags: ["nodejs_compat"]` |
| 加 `routes` 后 workers.dev 打不开 | 404 / error 1042 | 预期行为，安全默认值 |

### 8.2 D1

| 坑 | 现象 | 解 |
| --- | --- | --- |
| 不指定 `--location` | 库被建到代理出口所在区域（如 WNAM） | `--location=apac`，建完 `wrangler d1 info` 核对 `running_in_region` |
| 不指定 `--binding` | 绑定名变成 `cf_lab_db` | `--binding=DB` |
| 删库重建后配置残留 | 部署报数据库不存在 | 手动删掉指向已删库的 `d1_databases` 条目 |
| migration 只跑 `--local` | 本地全绿，线上 `no such table` | `--local` 和 `--remote` 是**两个独立数据库**，各跑一次 |
| 选了 `remote: true` 做本地开发 | 每次查询走公网；`DROP TABLE` 直接删线上数据 | 本地开发用本地模式 |
| 时间差 8 小时 | `datetime('now')` 返回 UTC | 前端 `new Date(s.replace(' ','T')+'Z')` |
| D1 当高频写库 | 写入慢 | D1 适合读多写少；高频写用 Durable Objects |

### 8.3 域名 / DNS

| 坑 | 现象 | 解 |
| --- | --- | --- |
| 想只接一个子域 | CF 报错或强制改成根域 | 免费版不支持子域委派，只能整域接管 |
| 扫描出的记录不全 | 迁移后某个子域打不开 | 自动扫描不保证全，**去原 DNS 控制台逐条核对** |
| 云朵默认橙色 | 国内用户变慢 + 备案风险 | **手动全部点灰**，只给要走 CF 的记录开橙云 |
| MX 记录挂橙云 | 邮件收不到 | 邮件走不了 HTTP 代理，MX 必须灰云 |
| 改错了地方 | 改了 DNSPod 解析记录但 NS 没变 | 改的是**注册商处的 DNS 服务器**，不是解析记录 |
| 看解析器判断迁移成功 | 以为没生效 | 递归解析器有缓存，用 **RDAP 查注册局**才是权威 |
| 橙云代理非标端口 | 8000/8001/8002 等端口不通 | 免费版橙云只代理特定端口（HTTP: 80/8080/8880/2052/2082/2086/2095；HTTPS: 443/2053/2083/2087/2096/8443） |
| 缓存规则写太宽 | 登录接口被缓存，所有人拿同一个 token | 缓存规则必须显式排除 `/api/` `/auth/` |
| SSL 模式选 Flexible | 重定向死循环 | 源站有真证书就选 **Full (strict)** |

### 8.4 环境 / 工具

| 坑 | 现象 | 解 |
| --- | --- | --- |
| Clash TUN 让测量失真 | 「国内直连」测出来仍是境外 | 见第七节 |
| WSL 没装 dig | `dig: command not found` | 用 DoH：`curl -H "accept: application/dns-json" "https://dns.alidns.com/resolve?name=x&type=A"` |
| `nslookup` 返回 198.18.x.x | 查到的是 TUN fake-ip | 同上，用 DoH |
| `wrangler login` 弹不出浏览器 | 卡住 | 复制终端 URL 手动打开；确认 `no_proxy` 含 `127.*` 和 `localhost` |
| `d1 execute` 输出被元数据刷掉 | 看不到查询结果 | 加 `--json` 再用 python 解析 |
